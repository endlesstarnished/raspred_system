# Лабораторная работа 01. Реализация RPC-сервиса с использованием gRPC

# Цель работы
1. Освоить принципы удаленного вызова процедур (RPC) и их применение
 в распределенных системах
2. Изучить основы фреймворка gRPC и языка определения интерфейсов
 Protocol Buffers (Protobuf)
3. Научиться определять сервисы и сообщения с помощью Protobuf
4. Реализовать клиент-серверное приложение на языке Python с
 использованием gRPC
5. Получить практические навыки в генерации кода, реализации  серверной
 логики и клиентских вызовов для различных типов RPC.

# Вывод
Вывод по лабораторной работе
В ходе выполнения лабораторной работы был успешно разработан и протестирован распределенный клиент-серверный сервис для системы опросов с использованием технологии gRPC. 
Работа выполнена в минимальной конфигурации с использованием только необходимых файлов, что позволило сосредоточиться на ключевых аспектах технологии. <br>
1. Проектирование и определение контракта сервиса <br> Был создан файл survey.proto, содержащий строго типизированное определение интерфейса сервиса.
В соответствии с вариантом задания №15 ("Система опросов") разработан сервис SurveyService с единственным методом SubmitAnswers, реализующим паттерн Client Streaming RPC.
Этот подход оптимально подходит для сценария, где клиенту необходимо отправить набор ответов на вопросы опроса одним потоком данных.
3. Автоматическая генерация кода <br> С помощью инструментария grpcio-tools осуществлена трансформация декларативного описания интерфейса в готовый Python-код.
Были автоматически сгенерированы файлы survey_pb2.py (содержащий классы сообщений) и survey_pb2_grpc.py (содержащий базовые классы сервера и клиента).
Этот подход демонстрирует одно из ключевых преимуществ gRPC — возможность автоматической генерации клиентских и серверных стабов для различных языков программирования на основе единого контракта.
5. Реализация Server-side логики <br> В файле server.py реализован класс SurveyService, наследующий от сгенерированного базового класса.
Метод SubmitAnswers принимает поток объектов Answer и обрабатывает их последовательно. Серверная часть демонстрирует: <br> Принцип обработки потоковых данных <br> Подсчет статистики полученных ответов <br>
Формирование агрегированного ответа клиенту <br> Асинхронную обработку запросов с использованием пула потоков
7. Реализация Client-side логики <br> Клиентская часть (client.py) создает тестовый набор из пяти ответов на вопросы опроса и отправляет их серверу в виде потока. Клиент демонстрирует: <br>
Установление соединения с сервером <br> Использование генератора Python для создания потока данных <br> Корректную обработку как успешных сценариев, так и возможных ошибок связи <br> Вывод результатов, полученных от сервера
8. Практическая демонстрация Client Streaming RPC <br> Работа наглядно показывает особенности Client Streaming RPC: <br> Клиент инициирует соединение и отправляет последовательность сообщений <br>
Сервер принимает поток данных, обрабатывает его и возвращает единственный ответ <br> Такой подход эффективен для загрузки файлов, отправки пакетных данных или, как в данном случае, для передачи ответов на опрос
